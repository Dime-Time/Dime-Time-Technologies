DIME TIME — AUTOMATIC DEBT IMPORT IMPLEMENTATION PLAN

PROJECT GOAL

Implement automatic debt import for Dime Time in a provider-agnostic way so the feature is production-ready and can be activated as soon as a liability-data provider (Plaid Liabilities, Method Financial, etc.) grants production access.

This project should NOT depend on Plaid production approval before development begins.

=========================================================
CURRENT STATE
=========================================================

Current payment provider:

• Stripe Financial Connections
  - Used for ACH transfers
  - Used for verified bank accounts
  - Used for balances and ownership
  - DOES NOT provide liability information

Current Plaid implementation:

• Link Token
• Token Exchange
• Accounts
• Transactions
• Auth

Current limitations:

• Sandbox only
• No Liabilities product
• No production approval
• Cannot retrieve real consumer debts

This means the blocker is provider approval—not engineering.

=========================================================
ARCHITECTURE GOAL
=========================================================

Build the entire debt-import feature now while keeping the data provider interchangeable.

DO NOT hardcode Plaid throughout the application.

Instead create a provider abstraction.

Example:

Debt Import Service

↓

Plaid Provider

Method Provider

MX Provider

Finicity Provider

Spinwheel Provider

This allows us to swap providers later with minimal code changes.

=========================================================
COMPLIANCE
=========================================================

Review implementation to ensure:

Explicit user consent before importing liabilities.

Privacy Policy accurately describes liability data collection and usage.

Collect only the fields necessary for debt management.

Encrypt liability data at rest and in transit.

Apply least-privilege access controls.

Maintain audit logs for imports and refreshes.

Document data retention and deletion behavior.

If future features involve credit decisions, underwriting, or sharing consumer financial information with third parties, flag those workflows for legal review because they may introduce additional regulatory obligations (including potential FCRA considerations).
