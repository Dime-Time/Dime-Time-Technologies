OVERALL ASSESSMENT

The release plan is approximately 85–90% complete. The overall sequence
is solid, but several production-grade validation steps should be added
before submitting Build 207 to Apple.

The largest remaining technical risk is ensuring Plaid OAuth functions
correctly during real-world Chase (or other OAuth institution) flows,
especially if any portion of the authentication process transitions
between a Capacitor WebView and native iOS.

====================================================================
2. UNIVERSAL LINK GOTCHAS
====================================================================

A. Apple CDN Caching

Even if:

https://dime-time.com/.well-known/apple-app-site-association

returns:

HTTP 200

Apple's CDN may temporarily cache older information.

Recommended approach:

• Enable capability
• Refresh provisioning profile
• Build new IPA
• Install fresh build
• Allow propagation if necessary
• Retest

------------------------------------------------------------

B. AASA Location

Preferred location:

https://dime-time.com/.well-known/apple-app-site-association

No .json extension.

------------------------------------------------------------

C. Content-Type

Verify response headers:

Content-Type:
application/json

Ensure:

• No redirects
• No authentication
• No HTML responses
• No CDN interference
• No geographic filtering

------------------------------------------------------------

D. Path Matching

Confirm the AASA file correctly allows:

/plaid/oauth

including OAuth query parameters.

The rebuilt pathname + search implementation appears correct.

------------------------------------------------------------

E. Universal Link Testing Sources

Do NOT only test from Safari.

Also test:

✓ Messages
✓ Mail
✓ Notes
✓ External webpage
✓ Plaid OAuth callback

------------------------------------------------------------

F. Scope of Claimed Paths

Avoid claiming every path on:

dime-time.com

if unnecessary.

Prefer only application routes such as:

/plaid/oauth
/reset-password/*
/app/*

Unknown routes should fail safely.

------------------------------------------------------------

G. Cold Start Race Conditions

Verify:

✓ App terminated
✓ Logged in
✓ Logged out
✓ Backgrounded
✓ Foregrounded
✓ OAuth callback during startup

Ensure callback URLs are retained until the router is ready.

------------------------------------------------------------

H. Duplicate Callback Handling

Multiple callback events should NEVER:

• Create duplicate Plaid Items
• Exchange tokens twice
• Duplicate imports
• Duplicate ACH activity

OAuth processing should remain idempotent.

------------------------------------------------------------

I. WebView Risk

Current highest functional risk.

If any portion of Plaid Link executes inside a Capacitor WebView:

Verify end-to-end success for:

• Chase OAuth
• Public Token exchange
• Item creation
• Debt import
• App relaunch

Successful authentication alone is NOT enough.

The complete Plaid lifecycle must succeed.
