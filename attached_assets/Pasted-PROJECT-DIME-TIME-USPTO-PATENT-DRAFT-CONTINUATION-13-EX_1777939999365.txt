3. Retrieves user allocation vector:
   The system retrieves the user-defined allocation vector V = [80%, 20%], where 80% is allocated to debt repayment and 20% is allocated to digital asset acquisition.

4. Applies allocation vector:
   The system calculates allocation portions:
   Debt allocation = $0.65 × 0.80 = $0.52

5. Creates ledger entry (state: CREATED):
   A new ledger record is created containing:
   - Transaction ID
   - Source account ID
   - Original transaction amount ($4.35)
   - Round-up amount ($0.65)
   - Allocation vector [80, 20]
   - Destination records for debt and Bitcoin
   - Initial state: CREATED

6. Transitions to CALCULATED:
   The system marks the ledger entry as CALCULATED after verifying round-up computation and allocation splits.

7. Aggregation phase:
   The system aggregates multiple round-up events until a minimum transfer threshold is reached.

8. Authorization phase (state: AUTHORIZED):
   Transfer authorization is requested and approved.

9. Transfer creation (state: PENDING):
   ACH transfer is created and submitted.

10. Posting phase (state: POSTED):
    Transfer is posted to the originating account.

11. Settlement phase (state: SETTLED):
    Funds settle in the funding account.

12. Destination routing execution:
    Debt portion routed to repayment account.
    Bitcoin portion routed to crypto purchase.

13. Destination completion:
    Debt: pending → posted → settled.
    Bitcoin: order placed → executed → credited.

14. Ledger reconciliation (state: RECONCILED):
    Final statuses, timestamps, and IDs are recorded.

15. Failure branch:
    If failure occurs:
    - State transitions to FAILED, RETURNED, or CANCELED
    - Retry logic may execute
    - User may be notified
    - Idempotency prevents duplication

16. User dashboard update:
    Displays updated debt reduction and asset accumulation.

ABSTRACT

A computerized financial microallocation system receives transaction data, calculates round-up amounts, applies an allocation vector, and distributes funds across multiple destinations including debt repayment and digital asset acquisition. The system supports continuous allocation ratios, multi-destination routing, real-time execution, idempotent processing, and reconciliation tracking.
