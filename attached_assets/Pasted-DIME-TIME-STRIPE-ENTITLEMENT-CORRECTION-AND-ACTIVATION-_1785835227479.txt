CRITICAL FINDING

The current entitlement logic reportedly grants subscription access for these Stripe statuses:

* active
* trialing
* incomplete
* past_due

This is too broad.

Stripe’s `incomplete` status generally means the first subscription invoice has not been successfully completed. Granting entitlement from `subscription.status === "incomplete"` alone could allow a user to begin creating a subscription, never complete payment, and still receive paid access.

ACH is a delayed-notification payment method, so Dime Time may provide limited provisional access while a legitimate ACH payment is processing—but that access must be based on the authoritative PaymentIntent and mandate state, not the `incomplete` subscription status alone.

2. REQUIRED ENTITLEMENT POLICY
==============================

Implement one centralized entitlement evaluator used by every server route and every client-facing subscription-status response.

Required policy:

ACTIVE

Grant normal paid entitlement only when:

* Stripe subscription status is `active`.
* The subscription belongs to the authenticated Dime Time user.
* The subscription uses the approved Dime Time Debt product/price.
* The subscription has not been revoked.
* Provider data passes integrity checks.

TRIALING

Grant trial entitlement only when:

* Stripe status is `trialing`.
* The trial belongs to the approved product.
* A trial is explicitly configured and approved by Tim.
* The trial expiration is valid.

Dime Time currently has no approved free trial. Do not create or advertise one. If no approved trial exists, a `trialing` state must be reported prominently as unexpected and must not silently grant permanent access.

INCOMPLETE

Do not grant normal paid entitlement solely because:

subscription.status === "incomplete"

An incomplete subscription without a qualifying ACH payment in progress must receive no paid access.

The following PaymentIntent states must not grant provisional or paid access:

* requires_payment_method
* requires_confirmation
* requires_action
* canceled
* failed or equivalent
* missing PaymentIntent
* PaymentIntent belonging to another invoice, subscription, customer, or user
* unsupported payment method
* absent or invalid mandate
* arbitrary client-supplied status

ACH PROCESSING — PROVISIONAL ACCESS

If Dime Time intentionally provides instant provisional access while the first ACH debit is processing, create a separate normalized state such as:

provisional_ach

Grant this state only when every condition is true:

* Subscription is for the approved Dime Time Debt price.
* Subscription belongs to the authenticated user.
* Latest invoice belongs to the same subscription.
* PaymentIntent belongs to the same invoice and customer.
* Payment method type is `us_bank_account`.
* PaymentIntent status is authoritatively `processing`.
* A valid ACH mandate/authorization exists.
* Processing began within the configured provisional-access window.
* No payment-failure, cancellation, dispute, refund, reversal, or revocation event has been received.
* The provisional-access expiration is persisted server-side.
* The client did not supply any trusted status field.

The provisional window must be explicit, finite, and documented. Use the existing approved duration if one already exists. If no duration is currently defined, do not invent one—return a business-decision requirement for Tim.

When provisional access expires without successful payment:

* Remove premium entitlement.
* Preserve the user’s account and data.
* Display an accurate payment-pending or payment-failed state.
* Provide a safe retry/recovery path.
* Do not create another subscription automatically.
* Do not initiate another debit automatically.

When the ACH payment succeeds:

* Process the signature-verified Stripe event.
* Transition the normalized entitlement to active.
* Clear the provisional expiration.
* Record the transition idempotently.

When the ACH payment fails, is canceled, disputed, returned, refunded, or reversed:

* Revoke provisional entitlement immediately.
* Preserve the account and user data.
* Display a truthful recovery message.
* Never leave the user entitled merely because the subscription remains incomplete.

PAST_DUE

Past-due access may be granted only through a defined, finite grace period.

Required conditions:

* The subscription was previously legitimately active.
* The subscription belongs to the authenticated user.
* The approved price is still attached.
* A server-computed `graceUntil` value exists.
* Current time is before `graceUntil`.
* The subscription has not become unpaid, canceled, revoked, or expired.
* Grace does not reset indefinitely when duplicate or out-of-order webhooks arrive.

After `graceUntil`, remove premium entitlement while preserving account data.

Do not grant indefinite access from `status === "past_due"`.

CANCELED AT PERIOD END

If the user cancels at period end and Stripe still reports the subscription as active:

* Continue access only through the verified paid current-period end.
* Display the cancellation date.
* Do not renew entitlement beyond that date without a valid renewal.

If Stripe status is fully canceled:

* Do not grant entitlement unless authoritative evidence proves a previously paid period remains valid under the pinned Stripe behavior.
* Do not rely on a client date.

NO ACCESS

These statuses must not grant normal paid entitlement:

* incomplete
* incomplete_expired
* unpaid
* canceled after valid access ends
* paused
* revoked
* refunded when the refund terminates entitlement
* missing
* unknown
* malformed
* unsupported product or price

Unknown provider states must fail closed and trigger safe diagnostics.
