REQUIRED IPHONE BOTTOM-NAVIGATION REVIEW
================================================================

PROBLEM

All authenticated iPhone screenshots show blurred page content beneath or
behind the fixed bottom-navigation bar.

Affected screenshots:

- Dashboard
- Debt Management
- Transactions
- Insights
- Crypto

The navigation icons and labels remain visible, but the blurred content
underneath resembles:

- Accidental censorship
- A screenshot-rendering problem
- A CSS stacking problem
- Content continuing beneath an insufficiently opaque navigation background

REQUIRED ACTION

Inspect the mobile bottom-navigation implementation.

Determine whether the blur is caused by:

- backdrop-filter
- backdrop-blur
- A translucent background
- Incorrect z-index
- Incorrect bottom padding
- Page content scrolling beneath the fixed navigation
- Screenshot-tool rendering differences
- An actual build-207 UI behavior

Preferred correction:

- Give the bottom navigation a fully opaque background using the correct Dime
  Time surface color.
- Ensure page content does not remain visibly readable or heavily blurred
  beneath the navigation.
- Preserve the navigation’s existing icons, labels, active state, and layout.
- Preserve safe-area padding.
- Ensure content is not hidden behind the navigation.
- Do not redesign the navigation.
- Do not introduce a large visual change into build 207.

After correcting:

1. Rebuild the current interface.
2. Recapture these four authenticated iPhone screenshots:

   - Dashboard
   - Debt Management
   - Transactions
   - Financial Insights

3. Keep the exact accepted size:

   1290 × 2796

4. Verify PNG, RGB, and no alpha channel.
5. Confirm the bottom navigation looks clean and intentional.
6. Compare the result to the actual TestFlight build.

If the blur exists only in the screenshot-rendering tool and not in TestFlight:

- Do not change production CSS solely based on an inaccurate renderer.
- Correct the capture method instead.
- Return evidence comparing the renderer with TestFlight.

If the blur exists in TestFlight:

- Fix it as a real UI issue.
- Rebuild/sync before the final build-207 archive if build 207 has not yet been
  uploaded.
- If Apple has already accepted build 207 for processing, report whether a new
  build number is required before changing the bundled frontend.

MISSING-CHARACTER / TOFU ICON REVIEW
================================================================

Observed issues:

- iPad Dashboard: unsupported/missing character before “DAILY TIP”
- iPad Activity: unsupported/missing characters before:
  - “Boost Your Round-ups”
  - “High-Interest First”

These appear as empty square boxes.

REQUIRED ACTION

Inspect the affected text/icon implementation.

Determine whether the source uses:

- Emoji
- Unicode characters
- Unsupported font glyphs
- Icon fonts that are unavailable in the capture environment
- A screenshot-renderer font limitation

Preferred correction:

- Replace unsupported glyphs with existing project SVG/Lucide icons.
- Do not rely on emoji rendering for important visual elements.
- Keep the text unchanged.
- Confirm the same supported icon renders on web, iPhone, and iPad.

At minimum:

- Fix or verify the DAILY TIP icon before using the Dashboard screenshot.
- Drop the Activity screenshot regardless, because its framing is weak.

If the missing squares occur only in the screenshot renderer:

- Correct the renderer or remove the unsupported icon from the screenshot output.
- Confirm they do not appear in TestFlight.
